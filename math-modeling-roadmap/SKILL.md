# 数学建模总体技术路线图

总体路线图让读者看清整篇论文如何从一问走到下一问。先核对当前正文、最终采用的模型与结果，再设计画布；历史算法、旧方案和参考图中的具体方法不能自动进入成品图。

## 构图

1. 为每一问写一句任务与产出，列出关键输入、决策、方法、结果。再单列跨问接口：前问哪些关系可沿用，哪些任务结构被冻结，哪些决策在新约束下重新求解。关系准确后再画框和箭头。
2. 按读者路线布置模块。每个模块只保留能识别该问的主要方法和必要的结果线索；详细公式、逐项参数及核验日志留在正文。图的面板数量、配色和子图数量由实际论文及用户选定样例决定。
3. 真实结果图只从已确认的成品图集中选取，保留原始数据含义与比例。缩图后若轴字、图例或标注读不清，选关键子图，或依据原始数据制作路线图专用简图；增加导出像素不能修复纸面物理字号。
4. 参考样例可确定画布比例、区域关系、色彩和线条风格；模块文字、箭头含义和所选结果图必须来自本研究。用户最新确认的样例优先于早期通用样式。

具体的内容取舍与纸面核验见 [设计和审阅依据](references/roadmap-method.md)。需要开始规划时，可复制 [路线图计划表](assets/roadmap-plan-template.md)。

## Excalidraw MCP 制作

先阅读 [MCP 操作与迭代流程](references/excalidraw-mcp-workflow.md)。以第三版 [PNG 与画布](examples/README.md)为本次方法的实例：可参考其错位四区、方法与结果并列和跨问关系，但新图仍以当前论文的内容为准。

1. 调用 `read_diagram_guide`，再用 `describe_scene` 查看现有画布。已有内容须先 `snapshot_scene` 或导出备份；只在空白或专用画布上使用 `import_scene(mode="replace")`。
2. 先批量建立分区、方法框和结果位置，再用稳定 ID 连接箭头。图形工具能表达的结构用 `batch_create_elements`、`update_element`、对齐和分布工具调整；复杂真实图件可先制作带内嵌资产的 `.excalidraw`，再通过 MCP 导入、回读和修订。不要把 Mermaid 自动布局当成最终纸面布局。
3. 用 `describe_scene` 和 `export_scene` 检查元素、连接、坐标及图像是否完整。有浏览器前端时，再 `set_viewport(scrollToContent=true)`、`get_canvas_screenshot`、`export_to_image`；无前端时改用源 PNG 或本地导出图做目视检查，并明确说明未完成 MCP 原生截图。
4. 按预计论文插入宽度看整图。若标题、箭头或关键结果看不清、遮挡或与正文不符，返回内容取舍或画布布局继续修改，重新导出并复查，直到通过。不能用高 DPI 代替纸面字号检查。

## 制作与交付

可用 Excalidraw、SVG 或其他可编辑工具；保留可编辑源、预览图和适合论文插入的导出文件。若文字转成字形路径，应说明位置和大小仍可编辑，但改字需回到文本源或生成代码。SVG 内嵌 PNG 时不能称整图全矢量。

按论文实际插入宽度渲染并审阅完整页面，再放大检查小图内部文字、箭头终点、遮挡、边界和不同问题之间的指向。记录结果图来源、图号、版本及必要的哈希；自动检查、目视检查和用户确认分别说明。每次不达标都记录改动与复查结果。需要参考成品时看 [第三版实例](examples/README.md)，借鉴组织方式，不复用本题数据。
