# 从本次正文写作 trace 提炼的实例

下列实例展示怎样作出写作决定。数字、算法和章节编号都属于原项目，不作为新论文的默认配置。

| 原项目中的写作情境 | 可复用的判断 |
|---|---|
| 数据预处理初稿缺少具体步骤，后稿补入字段含义、期限转换规则、真实示例与地形像元提取。 | “已经清洗数据”不足以解释模型输入；应写出影响后续建模的实际转换及输出。没有实施的处理不添加。 |
| 单点往返问题扩展为多点配送，共享飞机和电池又引入时序。 | 跨章先盘点继承的物理关系，再说明哪些条件变化使组批、路线和资源安排需要重求；章首与模型式子均要体现变化。 |
| 多点调度章节先写模型和求解，再写结果、验证、比较，最后回写问题分析。 | 先固定可核实的主体内容，再用问题分析解释真实方法；论文展示仍按读者理解顺序。 |
| 图与公式在最终正文中先有引出，后有符号或结果解释；孤立图题和重复数字曾被专项修订。 | 图表应承载一个读者判断。图前问题、图后发现和结论边界要与图实际呈现一致。 |
| 审查首稿时发现“主问题最优”容易被读成“完整调度最优”，并补明资源区间与实体设备分配的关系。 | 审阅优先寻找模型层次、实现和结论范围的错配，给出位置、证据与修法；语言润色不能代替这一步。 |
| 学术表达轮先列问题再改写，保留公式、数字、图表与限定；用户反馈后仍追加处理过长问题分析。 | 一轮审阅或程序检查通过不代表段落职责已妥当。根据具体反馈定点继续修订，无须固定轮次。 |
| 摘要在完整正文后逐问提取实际模型、关键结果与必要条件，并反查正文和定稿结果。 | 摘要是全文论证的压缩映射；历史算法、不同口径的比较数字和过宽的结论不应因篇幅短而混入。 |
| 参考文献先核实版本和出版信息，再记录每篇在正文中的具体用途；部分相关论文未收入文献表。 | 以主张决定引用，以原文和可靠元数据核实条目；相关不等于已被采用，也不必为凑数量而列出。 |
| 整合稿先指定各章来源版本，后期又逐项精简重复的“不能据此”说明。 | 合稿先锁定内容来源和指标口径；边界靠近相应结论交代，重复提醒可删，但不能删掉唯一的适用条件。 |

这些经验分别来自原项目的数据章、问题一至四撰写思路、第一版说明、各轮审查说明和最终正文。发布包保留的是方法判断；原项目路径、完整题解、候选日志与私有研究材料不作为本 skill 的运行依赖。
